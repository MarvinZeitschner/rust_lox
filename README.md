# rust_lox

Welcome to rust_lox.
This was my winter-semester-break-project, and is an interpreter for the Lox language written completely in rust.

I built this as a learning project using the extremely good book [Crafting Interpreters](https://craftinginterpreters.com/).
It passes the integration tests from Crafting Interpreters, and after a round of optimizations it's also reasonably quick for a tree-walking interpreter.

## What is this?

- A tree-walking interpreter for the Lox language (see the book above)
- Classes, inheritance, closures, the whole language
- A REPL for playing around
- Unit tests, the full Crafting Interpreters test suite, and benchmarks

## How do i run it?

You'll need [Rust](https://www.rust-lang.org/) installed.

Clone this repo.

```bash
git clone https://github.com/MarvinZeitschner/rust_lox
cd rust_lox
```

Run a script:

```bash
cargo run --release -- <path/to/your_file.lox>
```

Or start the REPL by leaving out the path (end it with Ctrl-D):

```bash
cargo run --release
> var name = "Lox";
> fun hi() { print "hi " + name; }
> hi();
hi Lox
```

Errors exit with `65` (syntax and resolver errors) or `70` (runtime errors), like in the book.

## How does it work?

The source goes through four stages:

1. **Lexer** (`src/lex`) turns the source into tokens. Tokens borrow their text from the source instead of copying it.
2. **Parser** (`src/parser`) is a recursive descent parser that builds the AST. On a syntax error it skips to the next statement and keeps going, so you see all errors at once.
3. **Resolver** (`src/interpreter/resolver.rs`) figures out for every local variable which declaration it refers to, and stores how many scopes up and at which slot it lives directly in the AST.
4. **Interpreter** (`src/interpreter`) walks the AST. Local variables live in `Vec`s indexed by the resolver's slots, globals in a hash map.

The AST node structs are generated by a small derive macro in `ast_macro`.

## Tests

I used all tests from the [Crafting Interpreters Github](https://github.com/munificent/craftinginterpreters) page, plus some regression tests of my own. So the language should be complete.

You can run them with

```bash
cargo test                                   # everything
cargo test --test integration -- closure/    # only the .lox tests matching a filter
```

Every `.lox` file in `test/` is a test, and new files are picked up automatically. The expectations are written as comments:

```lox
print 1 + 2;          // expect: 3
print nil.foo;        // expect runtime error: Only instances have properties.
var = 1;              // Error at '=': Expect variable name.
```

- `// expect:` lines must match stdout exactly and in order
- `// expect runtime error:` checks the message and exit code `70`
- `// Error` (or `// [line N] Error`) checks that a compile error is reported on that line and exit code `65`

## Benchmarks

`bench/` contains the benchmark programs from Crafting Interpreters. `benches/` uses [criterion](https://github.com/bheisler/criterion.rs) to measure every stage of the pipeline on smaller versions of them.

```bash
cargo bench                                  # everything
cargo bench -- interpret                     # only the interpreter
cargo bench -- --save-baseline before        # save a baseline before a change
cargo bench -- --baseline before             # compare against it afterwards
```

The HTML report ends up in `target/criterion/report/index.html`.

## Known limitations

- **Closures can leak memory.** Environments are reference counted, so a function declared inside another function keeps its environment alive and the environment keeps the function alive. That cycle is never freed. Fixing this properly would need a garbage collector.
- **The REPL reads one line at a time**, so a function has to fit on one line, and errors always report `[line 1]`.
- **Error messages** don't always match the book's wording. The tests only check the line and exit code for syntax errors.
